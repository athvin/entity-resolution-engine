# DupeZero feature inventory

Built 2026-11-20 from two sources: what the marketing site says (Source A) and
what the code does (Source B). It is an input to new marketing pages; nothing in
it is copy.

**How to read the status column**

| Status                | Meaning                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------ |
| VERIFIED              | Implemented, reachable by a customer in the web app, not behind a disabled flag, and covered by a test       |
| CLAIMED ONLY          | The site says it; no supporting code was found                                                               |
| IN CODE, NOT MARKETED | Implemented and reachable, but the site does not mention it. Needs confirmation before copy                  |
| PARTIAL OR HIDDEN     | Implemented but not reachable by a customer (staff-only, API-only, operator setup), incomplete, or not built |
| UNCLEAR               | Cannot be decided from the code; the notes say what is needed                                                |

**Two facts shape every row.**

1. **The backend API is not exposed to customers.** The production load
   balancer has one target group, the web app (`infra/terraform/envs/prod/edge.tf:199-245`);
   the API service is cluster-internal (`infra/k8s/charts/er-platform/templates/services.yaml`).
   Customer API keys can be minted only by staff (`rust/crates/er-server/src/lib.rs:10927-10990`).
   A capability that exists only as an API route is therefore PARTIAL OR HIDDEN,
   however complete it is.
2. **No Salesforce capability is reachable by a customer.** Connections and
   extracts exist as API routes only; there is no screen and no web-app route
   for them. Writing changes back to Salesforce is not built.

Paths: `FE` = `frontend/src`, `SRV` = `rust/crates/er-server/src`. Line ranges
are as of commit `9f905b1f`.

## Salesforce

> **Owner-confirmed, 2026-11-20:** DupeZero connects to customer systems
> through their APIs to pull records for deduplication, and has a Salesforce
> app listed on the Salesforce AppExchange. Neither is visible in this
> repository (no package source here; connections are API-only routes with no
> screen), so the rows below record what the code shows, and the solution pages
> now state the owner's account. Writing results back to Salesforce has not
> been confirmed and is still not claimed.
>
> **Owner-confirmed, 2026-11-20 (later):** once records are deduplicated,
> DupeZero writes the clean records back to the systems they came from, so
> every connected system holds the same deduplicated data. **No write path
> exists in this repository** (`SRV/writeback.rs` builds proposals and is
> called only from a test; no Salesforce or other write call exists), so this
> claim rests on the owner's account of the AppExchange app and integrations
> outside this repo. The site now states it; re-verify before launch.

## Other findings

- **Committed private keys**: `rust/crates/er-server/testdata/sa_token_test_rsa.pem`
  and `sa_token_rotated_test_rsa.pem`. They are referenced only by tests
  (`SRV/satoken.rs:303`, `rust/crates/er-server/tests/pg_satoken.rs:25`,
  `rust/crates/er-server/tests/pg_satoken/rotation.rs:16`), so they look like
  fixtures. They are not printed here. Confirm they never served production.
- **Salesforce client secrets stored unencrypted** (see the Salesforce section).
  Other secrets in the product are sealed with AES-256-GCM, so this one is the
  outlier.
- **Positioning**: Home presents an industry-independent entity-resolution
  product, `/pricing` presents a Salesforce dedupe tool, and the repo's
  `CLAUDE.md` describes a general dedupe API with Salesforce as the first
  integration. A Salesforce-led site has to reconcile these.
