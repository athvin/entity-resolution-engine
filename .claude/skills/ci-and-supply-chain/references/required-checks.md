# Jobs, contexts and the supply-chain lists

## Contents

- What is generated here, and what is not
- Every job per workflow, with its context, timeout and `if:` condition
- The `rust/deny.toml` advisory ignore list
- The allowed-licence list, mirrored into the frontend checker

Generated by `scripts/skills-check.sh regen` from the workflow files and
`rust/deny.toml`. Do not hand-edit below the marker.

Why generated: the advisory ignore list changes whenever an advisory is
published or resolved, job timeouts get raised when a dependency bump forces a
cold rebuild, and the set of jobs grows. A prose copy of any of it is wrong
within weeks.

Two things this file deliberately does **not** claim:

- **Which checks are required.** Branch protection is repository configuration,
  not a file in the tree, so it cannot be derived here. What is derived is each
  job's status-check **context** (the display name branch protection matches on)
  and its `if:` condition — and a job gated off pull requests can never be
  required.
- **That an ignore is still justified.** Each `deny.toml` entry carries its
  reasoning in the file itself. Read it there before assuming an ignore is
  still needed; they are meant to be removed when upstream moves.

Branch protection is repository configuration, not a file in the tree, so
the required set cannot be derived here. What *is* derived: every job, the
display name that becomes its status-check context, its timeout, and its
`if:` condition verbatim — a job gated off pull requests can never be a
required check. A `detect`-gated job reports `skipped`, which branch
protection accepts as satisfied; that is the whole reason the pattern
exists instead of a workflow-level `paths:` filter.

A context below containing `${{ matrix.* }}` is a MATRIX job, and its
per-leg names (`plan (core)`, …) **cannot be required**: when the job is
skipped by its `if:`, GitHub reports one check-run under the literal,
uninterpolated name shown here, so the per-leg contexts never report and
a PR that skips the tier blocks forever. Require a non-matrix aggregator
job instead — `terraform plan` is the worked example.

### Agentic workflows (`gh aw`)

Compiled to `*.lock.yml` by `gh aw compile`; edit the `.md`. **Never
required checks** — a required check that waits on a model would gate every
merge on a non-deterministic run, which is also why these are the only
workflows in this repo permitted a `paths:` filter.

**Mode** is `staged` when the workflow sets `safe-outputs.staged`, meaning
every output below is previewed in the run summary rather than applied: no
comment posted, no branch pushed, no issue opened. That is how an agent is
watched before it is trusted — remove the key to make it act.

| Workflow | Mode | Triggers | Safe outputs |
|---|---|---|---|
| `ci-triage.md` | live | `workflow_run`, `workflow_dispatch` | `add-comment`, `create-issue`, `noop` |
| `dependency-upgrade-pilot.md` | **staged** | `workflow_run`, `workflow_dispatch` | `add-comment`, `push-to-pull-request-branch`, `noop` |
| `generated-artifact-healer.md` | **staged** | `workflow_run`, `workflow_dispatch` | `push-to-pull-request-branch`, `add-comment`, `noop` |
| `skill-freshness-auditor.md` | live | `schedule`, `workflow_dispatch` | `create-pull-request`, `noop` |

### Advisory ignores in `rust/deny.toml`

Each entry carries a prose justification in the file itself. These gates are
**time-dependent** — they fail on advisories and yanks published since the
last green run, so a failure is usually not caused by the diff.

```toml
ignore = [
    "RUSTSEC-2024-0436",
    "RUSTSEC-2024-0449",
]
```
